2. pmtree 的方法

print / summary / coef / predict / logLik / objfun 与 coxph 的缺口

pmtree 对象同时是 constparty，因此 partykit 的全套工具 （nodeids()、nodeapply()、width()、depth()、[[）都能用。 本页只讲 model4you 自己定义的方法。本页所有输出都来自同一棵树：

library("model4you"); library("survival")
data("GBSG2", package = "TH.data")
bmod <- survreg(Surv(time, cens) ~ horTh, data = GBSG2, model = TRUE)
tr   <- pmtree(bmod, data = GBSG2)

print()

print(tr, node = NULL, FUN = NULL, digits = getOption("digits") - 4L,
      footer = TRUE, ...)

不带 node 时打印整棵树：

[1] root
|   [2] pnodes <= 3: n = 376
|       (Intercept)    horThyes
|         7.8590259   0.4001011
|   [3] pnodes > 3
|   |   [4] tgrade <= II: n = 223
|   |       (Intercept)    horThyes
|   |         7.2936454   0.3038557
|   |   [5] tgrade > II: n = 87
|   |       (Intercept)    horThyes
|   |         6.9808753   0.1630104

Number of inner nodes:    2
Number of terminal nodes: 3
Number of parameters per node: 2
Objective function: 2588.953

footer 里的 Objective function 是各节点 -logLik 之和， 是要最小化的量；logLik(tr) 给出的是相反数。

指定 node 时打印的内容完全不同——它会给出参数不稳定性检验的结果， 这是判断”这一刀切得有多硬”的直接依据：

print(tr, node = 1)
Partitioned model:
 survreg(formula = Surv(time, cens) ~ horTh, data = GBSG2, model = TRUE)
Partitioning variables: ~.
-- Node 1 --

Estimated parameters:
(Intercept)    horThyes
  7.6084486   0.3059506

Objective function:
2632.096

Parameter instability tests:
                 age   menostat        tsize        tgrade        pnodes       progrec
statistic  6.4963868  6.5410358 19.567796549  2.911335e+01  6.607655e+01 24.0458901830
p.value    0.4824638  0.4754703  0.001459297  1.483931e-05  2.066099e-13  0.0001710320
criterion -0.6586757 -0.6452532 -0.001460363 -1.483942e-05 -2.066099e-13 -0.0001710466
              estrec
statistic  7.2794468
p.value    0.3682583
criterion -0.4592747

每个候选分割变量一列，这就是 ctree 的参数不稳定性检验。 根节点上 pnodes 的 \(p = 2.1\times10^{-13}\) 远小于其余变量，所以第一刀切在它上面； age 与 menostat 的 \(p\) 接近 0.5，完全没有证据。 criterion 行是 ctree 内部用的尺度（log(1 - p) 一类的单调变换），排序与 \(p\) 值一致。

换个内部节点看，会发现候选变量的排序完全变了：

print(tr, node = 3)
Parameter instability tests:
                 age   menostat      tsize       tgrade      pnodes     progrec     estrec
statistic  3.2716489  5.2206817  2.5850916 17.608148579 11.80984413 14.48423487  6.4064500
p.value    0.9518204  0.6957728  0.9866297  0.003702417  0.05509907  0.01609234  0.4967040

在 pnodes > 3 这一支里，tgrade（\(p = 0.0037\)）压过了 progrec（\(p = 0.016\)）。 两者差距不大，这正是树结构不稳定的来源——第 1 页里 只要加上”两臂各 > 33 人”的约束，这一刀就改切 progrec 了。

警告这些 \(p\) 值是选择前的

它们衡量的是”在这个节点上，该变量与参数不稳定性的关联”， 默认 testtype = "Bonferroni" 只对同一节点内的候选变量个数做了校正， 没有对递归分割这个过程本身做任何校正。 不能把 \(p = 0.0037\) 当作”这个亚组真实存在”的证据。

coef()

coef(object, node = NULL, ...)

返回节点 × 参数的矩阵，行名是节点号：

  (Intercept)  horThyes
2    7.859026 0.4001011
4    7.293645 0.3038557
5    6.980875 0.1630104
注意单参数模型下返回的形状会变

coef.pmtree() 的实现是 t(sapply(info, function(x) x$coefficients))。 当每个节点只有一个系数时（例如 coxph 基模型），sapply 退化成向量， t() 把它变成 1 × 节点数的矩阵，列名还带上了节点号前缀：

     2.horThyes 4.horThyes 5.horThyes
[1,] -0.5611397 -0.1004515 -0.5612125

写自动化脚本时不要假定 coef(tr) 的行是节点—— 用 nodeapply(tr, ids = nodeids(tr, terminal = TRUE), function(n) n$info$coefficients) 更稳。

predict()

predict(object, newdata = NULL, type = "node", predict_args = list(),
        perm = NULL, ...)

三种 type：

type 返回 说明
"node"（默认） 终末节点号 最常用，用来给新病人分组
"coef" 该节点模型的系数 每行一个观测
"pass" 调用基模型的 predict() 参数经 predict_args 传入 
nd <- GBSG2[1:5, ]
predict(tr, type = "node", newdata = nd)
#> 1 2 3 4 5
#> 2 4 4 4 2

predict(tr, type = "coef", newdata = nd)
#>   (Intercept)  horThyes
#> 1    7.859026 0.4001011
#> 3    7.293645 0.3038557
#> 4    7.293645 0.3038557
#> 5    7.293645 0.3038557
#> 2    7.859026 0.4001011

predict(tr, type = "pass", newdata = nd)
#>       pred
#> 1 2588.997
#> 2 1993.209
#> 3 1993.209
#> 4 1993.209
#> 5 2588.997

## 传给 predict.survreg 的参数：中位生存时间
predict(tr, type = "pass", newdata = nd,
        predict_args = list(type = "quantile", p = 0.5))
#>       pred
#> 1 2019.683
#> 2 1526.692
#> ...
注意type = "coef" 返回的行名不可信

上面第二个输出的行名是 1, 3, 4, 5, 2，而 newdata 的行名是 1..5。 数值的顺序是对的（内部按 .id 排过序），错的只是行名： 实现里按节点分组构造 data.frame 再 rbind，行名在这个过程中被重新生成。

所以 cbind(newdata, predict(tr, type = "coef", newdata = newdata)) 是安全的 （按位置对齐），但 merge() 或任何按行名对齐的操作都会错。

perm 用来把指定变量的分割随机置换，是 varimp() 的底层机制， 也可以单独用来看某个变量对分组的影响有多大：

predict(tr, type = "node", newdata = GBSG2[1:8, ], perm = "pnodes")
#> 1 2 3 4 5 6 7 8
#> 4 4 2 2 2 5 2 4      # 与未置换的分组不同

logLik()

logLik(object, dfsplit = 0, newdata = NULL, weights = NULL, perm = NULL, ...)

各终末节点 logLik() 之和：

logLik(bmod)   #> 'log Lik.' -2632.096 (df=3)
logLik(tr)     #> 'log Lik.' -2588.953 (df=9)

df 默认是各节点模型自由度之和（3 个节点 × 3 个参数 = 9）， 不计入分裂本身消耗的自由度。dfsplit 就是用来补这一块的：

logLik(tr, dfsplit = 1)     # 每个分裂算 1 个自由度

用它做模型比较时要清楚：树是选出来的， 即便按 dfsplit 罚过，logLik 之差也不服从常规的 \(\chi^2\) 分布。 要检验”是否真有异质性”，用 pmtest()， 它靠参数自助法构造零分布。

当 newdata、weights 或 perm 任一非空时，函数改走 objfun() 通道， 此时 df 记为 NA；而 lm 基模型在这条通道上会直接 stop()：

Error: logLik not yet implemented for lm. Try objfun(..., sum = TRUE).

objfun()

objfun(x, newdata = NULL, weights = NULL, perm = NULL, sum = FALSE, ...)

默认返回每个观测的目标函数贡献，sum = TRUE 返回其和：

objfun(tr, sum = TRUE)
#> [1] -2588.953

head(objfun(tr), 3)                                  # 每人一个贡献值
#>         1         2         3
#> -8.230585 -8.291882 -7.907872

objfun(tr, newdata = GBSG2[1:50, ], sum = TRUE)      # 在新数据上评估

帮助页里的一句话值得照做：

Note that objfun.pmtree(x, sum = TRUE) is much faster than sum(objfun.pmtree(x))。

两者都对，但 sum = TRUE 是按节点批量算的，逐观测那条路径要对每一行单独调用一次。

objfun 与 logLik 对 glm、survreg 数值相同，对 lm 不同： objfun.lm 返回的是负平方误差，不是对数似然。详见 第 7 页。

coxph 基模型：能建树，但目标函数缺一块

DESCRIPTION 只承诺 lm/glm/survreg，但内部对 coxph 有专门处理： .modelfit() 里为 coxph 单独构造 score（cbind(mod$residuals, mod$residuals * model.matrix(mod))）， NEWS 在 0.9-6 还为它改过这段代码并支持了多治疗组绘图。

实测（GBSG2）：

cmod <- coxph(Surv(time, cens) ~ horTh, data = GBSG2, model = TRUE, x = TRUE)
trc  <- pmtree(cmod, data = GBSG2)
print(trc)
[1] root
|   [2] pnodes <= 3: n = 376
|         horThyes
|       -0.5611397
|   [3] pnodes > 3
|   |   [4] progrec <= 20: n = 144
|   |         horThyes
|   |       -0.1004515
|   |   [5] progrec > 20: n = 166

objfun 只有 lm、glm、survreg 三个方法（外加 pmtree、pmodel_identity）。 缺 objfun.coxph 的直接后果是：Cox 森林的变量重要性走不通， 换成 risk = function(x, ...) -as.numeric(logLik(x)) 也不行—— 实测在 varimp.cforest 内部报 replacement has length zero。

需要生存结局 + 变量重要性时，把基模型换成 survreg(..., dist = "weibull")（AFT，系数是 log 时间比）， 或者自己补一个 objfun.coxph 方法。补方法的写法见 第 7 页。

两个模型的目标量不同：coxph 的系数是 log HR，survreg 的是 log 时间比， 方向相反（治疗有益时前者为负、后者为正）。
