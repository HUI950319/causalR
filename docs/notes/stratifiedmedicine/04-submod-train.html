4. submod_train()：亚组识别

StratifiedMedicine 包函数手册

第 ③ 步，也是本包的核心。输入 \((Y, A, X)\)（可选 mu_train）， 输出每个人的亚组编号和一组可读的规则。

submod_train(Y, A, X, Xtest = NULL, mu_train = NULL, family = "gaussian",
             submod = "lmtree", hyper = NULL, ple = "ranger", ple.hyper = NULL,
             meta = ifelse(family == "survival", "T-learner", "X-learner"),
             propensity = FALSE, pool = "no", delta = ">0", param = NULL,
             resample = NULL, R = 20, resample_pool = NULL, R_pool = 20,
             stratify = ifelse(!is.null(A), "trt", "no"), combine = "SS",
             alpha_ovrl = 0.05, alpha_s = 0.05,
             verbose.resamp = FALSE, efficient = FALSE, ...)

参数多，但可以按用途分成四组：

组 参数 说明
建树 submod、hyper、Xtest 选哪种树、树的超参
CATE 来源 mu_train、ple、ple.hyper、meta、propensity 只有部分 submod 用得到，见下文
效应估计 param、alpha_ovrl、alpha_s、combine 建完树后顺手估一遍各亚组的效应
合并与重抽样 pool、delta、resample、R、resample_pool、R_pool、stratify 把亚组合并成治疗方案，或给估计加上重抽样区间

七种 submod

set.seed(1)
for (m in c("lmtree", "ctree", "ctree_cate", "rpart", "rpart_cate")) {
  r <- submod_train(Y, A, X, submod = m)
  cat(sprintf("%-11s %d 个亚组 | 切在: %s\n", m, nrow(r$Rules),
              summary(r)$`Variables that Define the Subgroups`))
}
#> lmtree      4 个亚组 | 切在: X1, X2
#> ctree       6 个亚组 | 切在: X2, X1, X26
#> ctree_cate  5 个亚组 | 切在: X40, X9, X3, X21
#> rpart       5 个亚组 | 切在: X1, X2, X50
#> rpart_cate  6 个亚组 | 切在: X1, X19, X11, X13, X18

真值是 \(X_1\)、\(X_2\)：只有 lmtree 干干净净地只切这两个变量。

按”检验什么”分成三类：

submod 底层函数 拟合的是 找到的是
lmtree partykit::lmtree \(Y \sim \text{MOB-OLS}(A \mid X)\) 预后 + 效应修饰（默认两者不分）
glmtree partykit::glmtree \(Y \sim \text{MOB-GLM}(A \mid X)\) 同上，二值结局
mob_weib partykit::mob + Weibull \(Y \sim \text{MOB-WEIB}(A \mid X)\) 同上，生存结局
ctree_cate partykit::ctree \(\widehat{\text{CATE}}(X) \sim \text{CTREE}(X)\) 效应修饰（两阶段）
rpart_cate rpart::rpart \(\widehat{\text{CATE}}(X) \sim \text{rpart}(X)\) 效应修饰（两阶段）
ctree partykit::ctree \(Y \sim \text{CTREE}(X)\) 纯预后
rpart rpart::rpart \(Y \sim \text{rpart}(X)\) 纯预后
otr partykit::ctree + 权重 \(\mathbb 1(\widehat{\text{CATE}} > \delta) \sim \text{CTREE}(X)\)，权重 \(\lvert\widehat{\text{CATE}}-\delta\rvert\) 最优治疗方案

默认值随 family 变："gaussian" → lmtree，"binomial" → glmtree， "survival" → lmtree（先对生存结局做 log-rank 变换 coin::logrank_trafo()， 再拟合 MOB-OLS）。

注记submod = "None" 同样只在 PRISM() 里存在 
submod_train(Y, A, X, submod = "None")
#> Error in get(submod, envir = parent.frame()): object 'None' not found

和 filter_train() 一样，submod_train() 用 get() 找同名函数。 不过 PRISM(submod = "None") 在 1.0.7 里也是坏的， 见第 8 页。

hyper：各树的超参数

重要帮助页写的 alpha = 0.05 与源码的 alpha = 0.1 不一致

submod_train 帮助页对 lmtree 和 glmtree 都写：

Default hyper-parameters are: hyper = list(alpha=0.05, maxdepth=4, parm=NULL, minsize=floor(dim(X)[1]*0.10))

而源码是：

StratifiedMedicine:::submod_lmtree
#> function (Y, A, X, alpha = 0.1, minsize = floor(dim(X)[1] * 0.1),
#>     maxdepth = 4, parm = NULL, ...)

实际默认是 0.1。这不是小事：本页后面那两个假亚组，其中一个的分裂 p 值是 0.062——在 0.05 下会被拒绝，在 0.1 下则被接受。

源码里的真实默认值：

submod alpha 大小约束 maxdepth 其它
lmtree 0.1 minsize = floor(0.10n) 4 parm = NULL
glmtree 0.1 minsize = floor(0.10n) 4 parm = NULL、link = "identity"、glm.fam = binomial
mob_weib 0.1 minsize = floor(0.10n) 4 parm = NULL
ctree / ctree_cate 0.1 minbucket = floor(0.10n) 4 —
rpart / rpart_cate 无此参数 minbucket = floor(0.10n) 4 帮助页写了 alpha，源码签名里没有
otr 0.1 minbucket = floor(0.10n) 4 delta = ">0"

调参的效果：

rules_of <- function(...) paste(submod_train(Y, A, X, submod = "lmtree", ...)$Rules$Rules,
                                collapse = " | ")
rules_of(hyper = list(alpha = 0.01))
#> [1] "X1 <= 0.016 | X1 > 0.016 & X2 <= 0.693 | X1 > 0.016 & X2 > 0.693"
rules_of(hyper = list(maxdepth = 2))
#> [1] "X1 <= 0.016 | X1 > 0.016"
rules_of(hyper = list(minsize = 250))
#> [1] "X1 <= 0.016 | X1 > 0.016"

maxdepth = 1 会让树一刀不切，而没有分裂的树会让 extract_rules() 崩溃：

submod_train(Y, A, X, submod = "lmtree", hyper = list(maxdepth = 1))
#> Error in data.frame(Subgrps = names(rules_vec), Rules = rules_rounded, : arguments imply differing number of rows: 0, 1

这意味着“没找到任何亚组”这件正常的事，在本包里表现为一个报错。 做阴性对照或严格调参时要用 tryCatch() 兜住。

parm：把 MOB 从”找预后”扳成”找效应修饰”

这是本页最有用的一条。

MOB 的分裂检验基于模型的得分函数。默认检验所有参数， 对 Y ~ A 这个节点模型来说就是 \((\beta_0, \beta_1)\)—— 其中 \(\beta_0\) 是截距，它不稳定意味着基线水平在变，那是预后差异。 parm = 2 只保留治疗系数那一列，于是分裂检验只对效应修饰敏感。

submod_lmtree() 把 parm 原样转发给 partykit::lmtree(parm = )，所以它真的生效：

submod_train(Y, A, X, submod = "lmtree")$Rules$Rules
#> [1] "X1 <= 0.016 & X2 <= -0.565" "X1 <= 0.016 & X2 > -0.565" 
#> [3] "X1 > 0.016 & X2 <= 0.693"   "X1 > 0.016 & X2 > 0.693"
submod_train(Y, A, X, submod = "lmtree", hyper = list(parm = 2))$Rules$Rules
#> [1] "X1 <= 0.016" "X1 > 0.016"

在 GBSG2 上对比更清楚。这份数据里 progrec（孕激素受体）是公认的效应修饰变量， pnodes（阳性淋巴结数）是强预后但非修饰因子：

library(survival)
data("GBSG2", package = "TH.data")
Ys <- with(GBSG2, Surv(time, cens))
Xs <- GBSG2[, !(colnames(GBSG2) %in% c("time", "cens", "horTh"))]
As <- GBSG2$horTh

submod_train(Ys, As, Xs, family = "survival", submod = "lmtree")$Rules
#>   Subgrps                       Rules
#> 1       3 pnodes <= 3 & progrec <= 90
#> 2       4  pnodes <= 3 & progrec > 90
#> 3       6  pnodes > 3 & progrec <= 20
#> 4       7   pnodes > 3 & progrec > 20
submod_train(Ys, As, Xs, family = "survival", submod = "lmtree",
             hyper = list(parm = 2))$Rules
#>   Subgrps         Rules
#> 1       2 progrec <= 21
#> 2       3  progrec > 21

默认切出 pnodes + progrec 四个亚组——pnodes 那一刀来自基线风险； 加上 parm = 2 之后只剩 progrec ≤ 21 / > 21， 正是文献里公认的那个效应修饰变量，切点由数据决定。

提示与 model4you::pmtree() 的对比

model4you 的内部函数 .modelfit() 同样有 parm 参数， 但 pmtree() 不转发它——传了不报错也不生效 （见model4you 手册）。 StratifiedMedicine::submod_train() 是这一族包里少数把 parm 真正接通的。

代价是功效下降：上面模拟数据里，parm = 2 只找到了 \(X_1\)， 漏掉了 \(X_2\)。检验的自由度从 2 降到 1，信号弱的修饰变量会被漏掉。 “只找修饰变量”和”把修饰变量找全”是一对权衡。

哪些 submod 需要 mu_train

源码里的条件是 if (cate_ind | param == "dr")—— 只有两阶段的 *_cate 方法，或者 param = "dr"，才会去拟合 ple 模型。 otr 不在 cate_ind 里，于是它默认就是坏的：

submod_train(Y, A, X, submod = "otr")
#> Error in data.frame(ind_PLE, X): arguments imply differing number of rows: 0, 800

两种修法，任选其一：

set.seed(2)
mu <- ple_train(Y, A, X, ple = "ranger", meta = "X-learner")$mu_train

## ① 显式传 mu_train
submod_train(Y, A, X, submod = "otr", mu_train = mu)$Rules
#>   Subgrps                      Rules
#> 1       2               X19 <= 0.840
#> 2       4 X19 > 0.840 & X13 <= 0.153
#> 3       5  X19 > 0.840 & X13 > 0.153

## ② 或者让 param="dr" 顺带把 ple 拟合出来
set.seed(2)
submod_train(Y, A, X, submod = "otr", param = "dr")$Rules
#>   Subgrps                      Rules
#> 1       2               X19 <= 0.840
#> 2       4 X19 > 0.840 & X13 <= 0.153
#> 3       5  X19 > 0.840 & X13 > 0.153
警告otr 在这份数据上有四成的概率”一刀未切”，而那也是报错

换五个种子重跑：

sapply(1:5, function(s) {
  set.seed(s)
  r <- tryCatch(submod_train(Y, A, X, submod = "otr", param = "dr"),
                error = function(e) NULL)
  if (is.null(r)) "一刀未切（报错）" else paste(nrow(r$Rules), "个亚组")
})
#> [1] "一刀未切（报错）" "3 个亚组"         "一刀未切（报错）" "4 个亚组"        
#> [5] "3 个亚组"

otr 的树建在 \(\mathbb 1(\widehat{\text{CATE}} > 0)\) 上，权重是 \(|\widehat{\text{CATE}}|\)。CATE 估计一噪声化，这棵树就切不动—— 而”切不动”在本包里是报错不是空结果，见第 8 页。

第一刀切在 X1（rpart_cate）或 X40（ctree_cate）上， 后续几刀是 X19、X11、X13、X30、X21——全是噪声变量。 原因在上一页已经给出： 这份数据上的 CATE 估计与真值的相关只有 0.21–0.37， 对它建树等于在噪声上建树。

同一份数据、同一批变量，一阶段的 lmtree 切对了 \(X_1\)、\(X_2\)， 两阶段的 rpart_cate / ctree_cate 全切在噪声上。 样本量不大时优先 MOB，这是本手册最实用的一条结论。

两阶段方法对 ple 的选择极其敏感。在 GBSG2 上做一次受控对比—— 只换 base-learner，树的方法不变：

for (b in c("linear", "ranger")) {
  set.seed(1)
  r <- submod_train(Ys, As, Xs, family = "survival",
                    submod = "rpart_cate", ple = b)
  cat(sprintf("ple = %-7s 切在: %s\n", b,
              summary(r)$`Variables that Define the Subgroups`))
}
#> ple = linear  切在: progrec, tgrade, pnodes
#> ple = ranger  切在: estrec, progrec, tsize

参数型的 linear（Cox）把 progrec 排在第一刀——对； 换成 ranger 之后第一刀切到了 estrec（雌激素受体）， 它与 progrec 高度共线（Spearman \(\rho \approx 0.6\)），是个典型的替身变量。

作为阴性对照，一阶段的 MOB 对 ple 完全不敏感——它根本不消费 mu_train：

identical(
  submod_train(Ys, As, Xs, family = "survival", submod = "lmtree", ple = "linear")$Rules,
  submod_train(Ys, As, Xs, family = "survival", submod = "lmtree", ple = "ranger")$Rules
)
#> [1] TRUE

重要默认 param 是 "lm"，不是帮助页写的 "dr"

param 的那段说明文字被 PRISM()、submod_train()、param_est() 三个帮助页共用， 写的是”gaussian / binomial 默认 dr“。但 submod_train() 的源码是：

if (is.null(param)) {
  if (family == "survival") param <- "cox"
  else                      param <- "lm"
}

而 PRISM() 的默认确实是 "dr"。同一棵树、同一份数据，两者给出不同的数字：

pool：把亚组合并成治疗方案

pool 不改变树，只是给每个亚组打一个 dopt 标签（该不该给治疗）， 再把同标签的亚组合并估计。

pool 判定方式
"no"（默认） 不合并
"trteff" 用亚组的朴素效应估计与阈值 delta 比较
"trteff_boot" 同上，但用 Bootstrap 估计
"otr:logistic" 以 \(\mathbb 1(\hat\mu_1-\hat\mu_0>\delta)\) 为结局、亚组为自变量的加权 logistic
"otr:rf" 同上，换成加权随机森林，并把 \(X\) 也放进去

小结

目标 配置
找效应修饰变量，样本量一般 submod = "lmtree" + hyper = list(parm = 2)
找效应修饰变量，样本量大、非线性强 rpart_cate / ctree_cate，但先验证 CATE 质量
只找预后亚组 submod = "ctree" 或 "rpart"
做治疗方案 submod = "otr" + mu_train，或 pool = "otr:logistic"
生存结局 lmtree（log-rank 变换）或 mob_weib；两者结论通常接近
