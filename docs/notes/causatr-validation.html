针对参考实现的验证

Validation against reference implementations · causatr 官方文档中译

来源：R 包 causatr 官方文档 validation.qmd，MIT 许可。 本页是中译，代码与运行结果直接取自原站的渲染输出，未在本站重新执行。 Copyright (c) 2026 causatr authors；许可证全文见原仓库 LICENSE.md。

causatr 围绕一个统一的影响函数引擎构建，它复现了若干专用 R 包所采用的三明治方差构造。 本文针对这些包逐一做并排比较，让你直接看到二者的一致（以及在预期之内的不一致）。 每一节都用 causatr 和一个参照实现拟合同一个因果量，并打印一张两行的表格， 给出点估计值、标准误和 95% CI。

什么算“一致”。 有些参照实现的是同一个估计量，应当吻合到很高的精度：

  • stdReg2::standardize_glm() 所用的 g-formula 影响函数与 causatr 的 point-gcomp 引擎 相同，因此点估计值应当吻合到 ~1e-6，SE 应当吻合到协方差求逆的舍入误差范围内。
  • WeightIt::glm_weightit() 所用的 M-估计量三明治与 causatr 的 IPW 分支 A 相同， 因此 SE 应当吻合到舍入误差范围内。
  • 对 MatchIt::matchit() 的输出以 vcov = ~subclass 调用 marginaleffects::avg_comparisons()，其聚类稳健汇总方式与 causatr 的匹配分支相同， 因此点估计值和 SE 应当吻合得很接近。

另一些参照实现的是另一个估计量，但瞄准同一个因果量。这种情况下，我们期待点估计值 一致（相差不超过有限样本噪声），但不期待 SE 的构造方式一致：

  • lmtp::lmtp_tmle() 是 TMLE，不是插入式 g-formula。它瞄准同一个因果参数， 但有限样本分布不同；二者一致只是一次合理性检查，不是正确性证明。

这里用到的包都在 Suggests 里；下面每个代码块都用 requireNamespace() 做了保护， 因此即使其中任何一个缺失，本文依然能正常构建。

准备工作

library(causatr)
library(tinytable)

compare_row <- function(label, result, name, ref_name,
                        ref_est, ref_se, level = 0.95) {
  con <- result$contrasts
  est <- result$estimates
  if (name %in% con$comparison) {
    row <- con[con$comparison == name, ]
  } else if (name %in% est$intervention) {
    row <- est[est$intervention == name, ]
  } else {
    stop(
      "name '", name,
      "' not found in result$contrasts$comparison or result$estimates$intervention"
    )
  }
  stopifnot(
    length(ref_est) == 1L && is.finite(ref_est),
    length(ref_se) == 1L && is.finite(ref_se)
  )
  z <- stats::qnorm(1 - (1 - level) / 2)

  # Three rows: causatr, reference, and a row of absolute differences.
  # The diff row is the whole point of the vignette — it makes
  # "do the two implementations agree?" visually obvious without making
  # the reader compare two numbers to 6 decimal places.
  est_c <- row$estimate
  se_c  <- row$se
  ci_lc <- row$ci_lower
  ci_uc <- row$ci_upper
  ci_lr <- ref_est - z * ref_se
  ci_ur <- ref_est + z * ref_se

  dt <- data.table::data.table(
    source   = c("causatr", ref_name, "abs diff"),
    estimate = c(est_c, ref_est, abs(est_c - ref_est)),
    se       = c(se_c,  ref_se,  abs(se_c  - ref_se)),
    ci_lower = c(ci_lc, ci_lr,   abs(ci_lc - ci_lr)),
    ci_upper = c(ci_uc, ci_ur,   abs(ci_uc - ci_ur))
  )

  tinytable::tt(dt, caption = label) |>
    tinytable::format_tt(
      j = 2:5, digits = 4, num_fmt = "decimal"
    ) |>
    tinytable::style_tt(i = 3, italic = TRUE, color = "#888")
}

compare_row() 从 causatr_result 中取出一个估计值（按名称取干预均值或对比）， 再配上一个参照估计值 + SE，并按正态近似给出 CI。输出是一张三行的 tinytable： causatr、参照实现，以及每一列上的绝对差异，这样是否一致（或不一致）一眼就能看出来。

为了可复现，我们用三个小规模模拟 DGP。用 NHEFS 也可以，但内联模拟能让本文自成一体， 渲染开销也低。各数据生成机制说明如下。

DGM 1：点处理（simulate_point()）

单个混杂因子 \(L\)、二值处理 \(A\) 和结局 \(Y\)（连续或二值，取决于 binary_outcome 标志）。两个版本共享相同的混杂结构：\(L\) 同时影响处理分配和结局。

连续结局（binary_outcome = FALSE）：

\[ \begin{aligned} L &\sim \mathcal{N}(0, 1) \\ A &\sim \text{Bernoulli}\bigl(\text{logit}^{-1}(0.4 \, L)\bigr) \\ Y &= 1 + 2 A + 0.5 \, L + \varepsilon, \quad \varepsilon \sim \mathcal{N}(0, 0.8^2) \end{aligned} \]

\(A\) 的结构系数为 2，因此真实 ATE 恰好为 2。

二值结局（binary_outcome = TRUE）：

\[ \begin{aligned} L &\sim \mathcal{N}(0, 1) \\ A &\sim \text{Bernoulli}\bigl(\text{logit}^{-1}(0.4 \, L)\bigr) \\ Y &\sim \text{Bernoulli}\bigl(\text{logit}^{-1}(-0.5 + 0.8 \, A + 0.3 \, L)\bigr) \end{aligned} \]

条件比值比为 \(\exp(0.8) \approx 2.23\)。

DGM 2：纵向二值（simulate_longitudinal()）

\(K\) 个时期，含二值处理、一个时变混杂因子和一个随访结束时的二值结局。存在 处理—混杂因子反馈：过去的处理会平移下一期混杂因子的分布。

\[ \begin{aligned} L_k &\sim \mathcal{N}(0, 1) + 0.3 \, A_{k-1} \quad (A_0 \equiv 0) \\ A_k &\sim \text{Bernoulli}\bigl(\text{logit}^{-1}(0.3 \, L_k)\bigr) \\ Y &\sim \text{Bernoulli}\!\left(\text{logit}^{-1}\!\left(-1 + 0.4 \sum_{k=1}^{K} A_k + 0.2 \, L_K\right)\right) \end{aligned} \]

处理—混杂因子反馈（\(L_k\) 依赖于 \(A_{k-1}\)）意味着朴素地对时变混杂因子做条件化会 产生偏倚；需要 G-computation（ICE）或带序贯权重的 IPW。

DGM 3：纵向连续（simulate_longitudinal_continuous()）

\(K\) 个时期，含连续（高斯）处理和连续结局。与 DGM 2 相同的处理—混杂因子反馈 结构，但全程使用连续变量。

\[ \begin{aligned} L_k &\sim \mathcal{N}(0, 1) + 0.2 \, A_{k-1} \quad (A_0 \equiv 0) \\ A_k &\sim \mathcal{N}(0.3 \, L_k,\; 1) \\ Y &= 1 + \sum_{k=1}^{K} A_k + 0.3 \, L_K + \varepsilon, \quad \varepsilon \sim \mathcal{N}(0, 0.5^2) \end{aligned} \]

在给每个时期的处理都加 1 的 shift(+1) 干预下，每个时期对结局恰好贡献 1 个单位， 因此 shift(+1) 相对自然值的真实因果效应为 \(K\)。在默认的 \(K = 2\) 下，真值为 2。

simulate_point <- function(n = 2000, seed = 1L, binary_outcome = FALSE) {
  set.seed(seed)
  L <- stats::rnorm(n)
  A <- stats::rbinom(n, 1L, stats::plogis(0.4 * L))
  if (binary_outcome) {
    Y <- stats::rbinom(n, 1L, stats::plogis(-0.5 + 0.8 * A + 0.3 * L))
  } else {
    Y <- 1 + 2 * A + 0.5 * L + stats::rnorm(n, sd = 0.8)
  }
  data.frame(L = L, A = A, Y = Y)
}

simulate_longitudinal <- function(n = 500L, K = 3L, seed = 2L) {
  set.seed(seed)
  L <- matrix(0, n, K)
  A <- matrix(0L, n, K)
  for (k in seq_len(K)) {
    L[, k] <- stats::rnorm(n) +
      if (k == 1L) 0 else 0.3 * A[, k - 1L]
    A[, k] <- stats::rbinom(n, 1L, stats::plogis(0.3 * L[, k]))
  }
  Y <- stats::rbinom(n, 1L, stats::plogis(-1 + 0.4 * rowSums(A) + 0.2 * L[, K]))
  wide <- data.table::data.table(id = seq_len(n))
  for (k in seq_len(K)) {
    wide[[paste0("L", k)]] <- L[, k]
    wide[[paste0("A", k)]] <- A[, k]
  }
  wide$Y <- Y
  wide[]
}

simulate_longitudinal_continuous <- function(n = 400L, K = 2L, seed = 3L) {
  set.seed(seed)
  L <- matrix(0, n, K)
  A <- matrix(0, n, K)
  for (k in seq_len(K)) {
    L[, k] <- stats::rnorm(n) +
      if (k == 1L) 0 else 0.2 * A[, k - 1L]
    A[, k] <- stats::rnorm(n, mean = 0.3 * L[, k], sd = 1)
  }
  Y <- 1 + rowSums(A) + 0.3 * L[, K] + stats::rnorm(n, sd = 0.5)
  wide <- data.table::data.table(id = seq_len(n))
  for (k in seq_len(K)) {
    wide[[paste0("L", k)]] <- L[, k]
    wide[[paste0("A", k)]] <- A[, k]
  }
  wide$Y <- Y
  wide[]
}

1. 单时点 G-computation vs stdReg2

stdReg2::standardize_glm() 实现的是参数化 g-formula，其影响函数三明治方差与 causatr 在 point-gcomp 分支中所用的完全相同。两者在这里应当吻合到只差舍入误差。

1a. 连续结局，风险差

df_pt <- simulate_point(n = 2000, binary_outcome = FALSE)

fit_gcomp <- causat(
  df_pt,
  outcome = "Y",
  treatment = "A",
  confounders = ~L,
  estimator = "gcomp",
  model_fn = stats::glm
)
res_gcomp <- contrast(
  fit_gcomp,
  interventions = list(a1 = static(1), a0 = static(0)),
  reference = "a0",
  type = "difference",
  ci_method = "sandwich"
)

3. 匹配 vs MatchIt 上的 marginaleffects

4. 纵向 ICE vs lmtp::lmtp_tmle

5. AIPW vs delicatessen（Python）

AIPW 引擎与 delicatessen (Zivich 等 2022) 做交叉验证，后者是一个 Python 的 M-估计库，为 AIPW 实现了同样的堆叠估计方程三明治方差 (Robins, Rotnitzky, 和 Zhao 1994)。由于 Python 不是测试套件的依赖，交叉核对使用的是 data-raw/aipw_reference.py 在同一 DGP 上（同一随机种子、同一份写入 CSV 的数据） 预先算好的参考值：

  • 二值处理、线性高斯 DGP、n = 5000、seed = 42：μ₁、μ₀、ATE 以及三个三明治 SE 与 delicatessen 在小数点后 4 位上一致。
  • 连续处理、平移 δ = 1、线性高斯 DGP、n = 5000、seed = 99：μ_shift、μ_natural 以及对比的 SE 与 delicatessen 在小数点后 4 位上一致（前推密度比公式 W_i = exp(δ(A_i − μ(L_i) − δ/2) / σ²)）。

这些参考值以 tolerance = 0.005 固定在 test-aipw.R 中。完整的堆叠 EE Python 实现见 data-raw/aipw_reference.py。

6. 其他参考

还有几个 R 包可以进一步扩展这套验证集：

  • gfoRmula 在宽表纵向数据上实现参数化 g-formula，是与 causatr 的 ICE 引擎 最直接对应的同类。它的干预设定更繁琐（intvars、interventions、 int_descript 一堆列表），但在静态的“always vs never”上做一次对比，会是 4a 节 很自然的补充。
  • survey::svyglm()（配合用户自己提供的权重列）是调查加权 IPW 的标准参照。 由于 causatr 已经在测试里验证了调查权重的处理——包括 causat(weights = svydesign(...)) 这条直接的便捷路径，它会自动把设计对象的 抽样权重和第一阶段 PSU 提取到对比阶段的聚类里——在 vignette 里再做一次对比 基本上只是重复这部分覆盖。
  • sandwich::vcovCL() 是 causatr 通用聚类稳健三明治方差 （causat(cluster = ...) / contrast(cluster = ...)）的标准答案。在饱和的 Y ~ A + L 模型上，经过 G/(G-1) 小聚类校正之后，两者的一致性在 test-cluster-sandwich.R 中被固定到机器精度。

如果你想为其中某个包（或这里没有列出的包）贡献一份参照对比，欢迎提 issue—— 套路和第 1–4 节一样：用两种方式拟合同一个量，把两者都传给 compare_row()， 再打印出得到的两行表格。
