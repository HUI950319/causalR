  1. 区分训练集、验证集与测试集。

  2. 理解损失函数、风险与交叉验证的概念。

  3. 针对待估的泛函参数，选择合适的损失函数。

  7. 用 origami R 包为超级学习器搭好合适的交叉验证结构。

引言

沿着《靶向学习路线图》，本章开始细谈估计这一步。为了得到目标参数的估计，我们需要决定如何评价估计流程的表现好坏。任何算法（估计量）的表现（或者说误差），对应的是它对来自同一数据生成过程的独立数据集的泛化能力。评估算法的表现极其重要——它给出算法表现好坏的定量度量，并指导我们在一组（或称一个”库”的）算法中作出选择。为了评估一个算法或一个算法库的表现，我们引入损失函数的概念，它定义了风险（risk），也就是期望预测误差。我们的目标是估计估计量的真实表现（风险）。下一章我们会细谈如何估计一个算法库中各算法的表现，以便挑出表现最好的那个。下文中，我们提出一种借助观测数据和 origami 包 (Coyle 和 Hejazi 2018; Coyle 等, 不详) 中实现的交叉验证流程来做到这一点的方法。

背景

理想情况下，在数据充裕的场景中（即观测数不受限），我们会把数据集分成三部分：

  1. 训练集，
  2. 验证集，以及
  3. 测试集（或称留出集）。

训练集用来拟合所关心的算法；我们在验证集上评估拟合结果的表现，验证集可用来估计预测误差（例如用于算法调参或选择）。所选算法的最终误差则由测试集（留出集）给出，这部分数据被完全隔离开来，直到最后的模型评估环节之前，算法从未接触过这些观测。有人可能会问：既然训练数据现成可用，为什么不直接用训练误差来评估所提算法的表现？遗憾的是，训练误差是拟合后算法泛化能力的有偏估计，因为它用同一批数据既做拟合又做评估。

由于数据往往稀缺，把数据集拆成训练、验证、测试三份可能限制过大，因为这会让可用于训练的数据少得太多。在没有大数据集、也没有专门测试集的情况下，我们必须诉诸那些通过高效地重复利用样本来估计算法真实表现的方法。重抽样方法（例如自助法）的做法是：从训练集中反复抽样，并把算法拟合到这些样本上。重抽样方法虽然常常计算量很大，但在评估算法、以及在一组算法中作选择时格外有用。此外，相比只把算法在全部训练数据上拟合一次，它们还能让我们更了解拟合结果的变异性与稳健性。

引入：交叉验证

本章我们聚焦于交叉验证——一件评估任意算法如何从样本推广到其所来自的目标总体的基本工具。交叉验证已在现代统计学的各个方面得到广泛应用，其中或许以统计机器学习最为突出。已经证明，在大样本（即渐近）意义下，交叉验证流程对于算法选择是最优的。具体而言，当估计被应用于从预测变量与结局的联合分布中抽取的独立样本时，交叉验证后的算法估计的是真实风险。

用于模型选择时，交叉验证具有强有力的最优性性质。渐近最优性结果表明，交叉验证选择器（在风险意义下）渐近地表现得与最优的先知（oracle）选择器一样好——后者是一个可以自由获知真实但未知的数据生成分布的假想流程。关于这些理论结果的更多细节，建议参阅 van der Laan 和 Dudoit (2003)、van der Laan, Dudoit, 和 Keles (2004)、Dudoit 和 van der Laan (2005) 与 van der Vaart, Dudoit, 和 van der Laan (2006)。

origami 包提供了一套交叉验证工具。下文中，我们会介绍 origami 中现成可用的各类交叉验证方案，介绍该包的总体结构，并演示这些流程在各种应用场景中的用法。

估计路线图：这些是怎么拼到一起的？

与我们定义《靶向学习路线图》的方式类似，我们可以定义估计路线图，作为估计过程的指南。具体来说，统一的基于损失的估计框架 (van der Laan 和 Dudoit 2003; van der Laan, Dudoit, 和 Keles 2004; Dudoit 和 van der Laan 2005; van der Vaart, Dudoit, 和 van der Laan 2006; van der Laan, Polley, 和 Hubbard 2007) 依赖交叉验证来构造、选择估计量并评估其表现，它由三个主要步骤构成：

  1. 损失函数： 把目标参数定义为期望损失（风险）的最小化元，所选的完整数据损失函数要能代表我们想要的表现度量。这里的完整数据，指的是包含（例如）缺失过程在内的完整数据。再把完整数据损失函数映射为观测数据损失函数，二者期望相同，并由此得到风险的估计量。

  2. 算法： 构造一个关于所关心参数的有限候选估计量集合。

  3. 交叉验证方案： 施用合适的交叉验证，并用交叉验证风险在候选者中选出表现最好的估计量。评估最终所得估计量的整体表现。

示例：交叉验证与预测

介绍完估计路线图之后，我们可以用预测为例，更精确地界定我们的目标。设观测数据为 \(O = (W, Y)\)，单元层面的数据结构可写作 \(O_i = (W_i, Y_i)\)，\(i = 1, \ldots, n\)。我们记 \(Y_i\) 为所关心的结局／因变量，\(W_i\) 为 \(p\) 维的协变量（预测变量）集合。我们假定这 \(n\) 个单元是独立的（或条件独立的）且同分布的。记 \(\psi_0(W)\) 为所关心的目标参数，也就是我们希望估计的那个量（estimand）。在这个例子中，我们关心的是在给定协变量条件下结局的条件期望，\(\psi_0(W) = \E(Y \mid W)\)。按照估计路线图，我们选择合适的损失函数 \(L\)，使得 \(\psi_0(W) = \text{argmin}_{\psi} \E_0[L(O, \psi(W))]\)。注意，真实目标参数 \(\psi_0(W)\) 是风险（所选损失函数的期望值）的最小化元。对于连续结局的条件期望，合适的损失函数可以是均方误差。于是我们可以把 \(L\) 定义为 \(L(O, \psi(W)) = (Y_i -\psi(W_i)^2\)。注意，能够估计该 estimand 的算法可以有很多（即很多不同的 \(\psi\)）。我们怎么知道 \(\psi_0(W)\) 的各个候选估计量各自做得如何？为了挑出表现最好的候选估计量并评估其整体表现，我们使用交叉验证。训练集中的观测用来拟合（训练）估计量，验证集中的观测用来评估（验证）它的风险。

接下来，我们引入一套足够灵活、能表示任意交叉验证方案的记号。具体地，我们定义一个划分向量 \(B_n = (B_n(i): i = 1, \ldots, n) \in \{0,1\}^n\)。

\(B_n\) 的一次实现定义了把数据随机划分为训练子集与验证子集的一种方式，使得

\[B_n(i) = 0, \ \ \text{第 i 个样本属于训练集}\] \[B_n(i) = 1, \ \ \text{第 i 个样本属于验证集。}\]

我们可以进一步把 \(P_{n, B_n}^0\) 与 \(P_{n, B_n}^1\) 分别定义为训练集与验证集的经验分布。于是 \(n_0 = \sum_i (1 - B_n(i))\) 与 \(n_1 = \sum_i B_n(i)\) 分别表示训练集与验证集中的样本数。划分向量 \(B_n\) 的具体分布，定义了交叉验证方案的类型，可针对手头的问题与数据集来定制。

origami 中的交叉验证方案

存在多种不同的划分方案，各自针对所关心问题的关键细节而设计，这些细节包括数据规模、结局的发生率，以及依赖结构（单元之间或跨时间）。下文中，我们介绍 origami 包中可用的各种交叉验证方案，并进而在实际数据分析示例中演示它们的用法。

留出（Holdout）

留出法，又称验证集方法，做法是把可用数据随机分成训练集与验证（留出）集。随后用训练集中的观测拟合（“训练”）模型，再用验证集中的观测来评估（“验证”）它。通常数据集会按 \(60:40\)、\(70:30\)、\(80:20\) 甚至 \(90:10\) 的训练／验证比例来划分。

留出法直观且计算开销小；但它确实有一个缺点：如果我们把”随机划分数据为训练集与验证集”这个过程重复一遍，得到的经验风险交叉验证估计可能差别很大。具体而言，在验证集上求得的损失函数经验均值（即经验风险）可能高度变异，取决于哪些样本被分进了训练与验证。总体来看，留出法的交叉验证经验风险变异更大，因为它还包含了随机划分本身带来的变异——这并不理想。对于分类问题（结局变量为二值或分类），还有一个额外缺点：训练集与验证集中两类（或多类）结局的分布可能失衡，导致训练好而验证差，或者反过来——不过这可以通过在交叉验证过程中引入分层来纠正。最后请注意，我们并没有把全部数据都用于训练或评估所提算法的表现，这本身就可能引入偏倚。

留一（Leave-one-out）

留一交叉验证方案与留出法密切相关，因为它同样把数据集分成训练集与验证集；只不过它不是把数据集划成大小相近的几份，而是用单个观测作为验证集。这样一来，绝大多数抽样单元都被用于拟合（训练）候选学习算法。由于只有单个抽样单元（例如 \(O_1 = (W_1, Y_1)\)）被排除在拟合过程之外，留一交叉验证可以给出偏倚更小的风险估计。通常，留一法不会像留出法那样高估风险。另一方面，由于风险估计基于单个抽样单元，它通常是一个高度变异的估计。

我们可以不断重复”把数据集拆成训练集与验证集”这一过程，直到每个抽样单元都当过一次验证集。沿用上面的例子，留一交叉验证方案的下一轮可能用 \(O_2 = (W_2, Y_2)\) 作验证集（之前扮演该角色的是 \(O_1 = (W_1, Y_1)\)），而其余 \(n-1\) 个抽样单元进入训练集。把这个做法重复 \(n\) 次，就得到 \(n\) 个风险估计，例如 \(MSE_1, MSE_2, \ldots, MSE_n\)（这里是以单元 \(i\) 为验证集时的均方误差 MSE 估计）。真实风险的估计就是这 \(n\) 个留一风险估计的平均。留一交叉验证方案给出的风险估计虽然比留出法偏倚更小（但变异更大），但当 \(n\) 很大时，它的计算开销可能非常高。

\(V\) 折（\(V\)-fold）

留一方案的一个替代是 \(V\) 折交叉验证。这一方案把数据集随机划分为 \(V\) 个大小相等（或近似相等）的部分。对每个部分 \(v=1,\ldots,V\)，第 \(v\) 折由第 \(v\) 个部分（它构成第 \(v\) 折的验证集）及其补集（构成第 \(v\) 折的训练集）定义。算法被分别拟合 \(V\) 次，对应 \(V\) 个训练集。随后通过验证集上得到的预测来评估每一折所拟合算法的风险。一个已拟合算法的交叉验证风险（例如 MSE），就是它在所有折上的平均风险。在 \(V\) 折交叉验证下，所有观测都参与了训练与验证两个阶段，从而避免候选学习算法只对数据的某个子集（例如某个给定的训练集）过拟合。

对于有 \(n\) 个抽样单元的数据集，取 \(v=n\) 的 \(V\) 折交叉验证就退化为留一法。类似地，若令 \(n=1\)，就能得到留出法对候选学习算法表现的估计。除了计算上的优势之外，\(V\) 折交叉验证往往能给出对真实底层风险更准确的估计。其根源在于这两种交叉验证方案所对应的偏倚—方差权衡不同：留一方案偏倚可能更小，但方差大得多（因为验证集中只有单个单元）。当 \(n\) 远大于 \(v\) 时，这一差别会更加明显。在 \(V\) 折交叉验证方案下，我们最终是在 \(v\) 个验证折上对风险估计取平均，而这些估计之间的相关性通常低于留一拟合所得风险估计之间的相关性。由于许多高度相关的量的均值具有更高的方差，留一法的风险估计方差会高于相应的 \(V\) 折交叉验证估计。

现在，让我们看看 origami 中的 \(V\) 折交叉验证怎么用！下一章我们会转向研究超级学习器算法——一种能够从大量候选学习算法构成的库中选出”最佳”算法的算法——我们既想拟合它，也想评估它的表现。超级学习器算法默认采用 \(V\) 折交叉验证方案。要设置 \(V\) 折交叉验证，我们需要调用 origami 的 folds_vfold(n, V) 函数。folds_vfold(n, V) 的两个必需参数是：待交叉验证的样本单元总数，以及我们希望划分的折数。

蒙特卡洛（Monte Carlo）

在蒙特卡洛交叉验证方案中，我们不放回地随机选取数据的某个比例构成训练集，其余抽样单元归入验证集。这样，数据集就被随机分成两个独立的部分：一个含 \(n_0 = n \cdot (1 - p)\) 个观测的训练集，和一个含 \(n_1 = n \cdot p\) 个观测的验证集。把这个过程重复很多次，蒙特卡洛交叉验证方案就随机生成了许多组训练／验证划分。

由于各折之间的划分是独立的，同一个观测单元可以多次出现在验证集中；请注意，这是蒙特卡洛方案与 \(V\) 折方案之间一个显著的区别。对于给定的抽样比例 \(p\)，若能重复无穷多次，蒙特卡洛交叉验证方案将是最优的——当然，这在计算上并不可行。借助蒙特卡洛交叉验证，可以探索比 \(V\) 折交叉验证多得多的数据集划分，从而（可能）得到（跨划分而言）变异更小的风险估计，但代价是偏倚增大（因为这些划分之间相关）。由于蒙特卡洛交叉验证生成的众多划分在抽样单元上有重叠，要达到 \(V\) 折交叉验证仅用 \(V\) 个划分就能达到的（无偏性意义上的）表现水平，需要更多划分，因而也需要更多计算时间。

下面我们用 origami 的 folds_montecarlo(n, V, pvalidation) 函数演示蒙特卡洛交叉验证方案的用法。要设置 folds_montecarlo(n, V, pvalidation)，我们需要：

  1. 希望交叉验证的观测总数；
  2. 折数；以及
  3. 放入验证集的观测比例。

与蒙特卡洛交叉验证方案一样，自助法交叉验证方案同样是随机选取抽样单元构成训练集，其余抽样单元归入验证集；区别在于这里是有放回抽样。这个过程随后被重复多次，每次都随机生成新的训练／验证划分。与蒙特卡洛方案不同的是，各折中训练集与验证集的单元总数（即两部分的大小）并不固定。另外，顾名思义，抽样是有放回进行的（如同自助法 (Davison 和 Hinkley 1997)），因此完全相同的观测单元可能出现在多个训练集中。验证集中观测单元所占的比例是一个随机变量，其期望约为 \(0.368\)。

滚动原点（Rolling origin）

滚动原点交叉验证方案很适合”在线”学习算法——在这类场景中，大量数据流必须被持续地（且尊重时间顺序地）拟合，学习算法的拟合会随着数据不断累积而（持续）更新。一般而言，滚动原点方案先定义一个初始训练集，随后每迭代一次，训练集就增长一批 \(m\) 个观测，验证集大小保持不变；训练时间与验证时间之间可能存在一个大小为 \(h\) 的间隔（滞后窗口）；不断加入新的折，直到验证集触及时刻 \(t\) 为止。训练集中包含的时间点始终落后于验证集中的时间点。

为进一步说明滚动原点交叉验证，下面展示一个产生三折的例子。这里第一个窗口为十五个时间点，我们先在其上训练候选学习算法。随后我们在十个时间点上评估它的表现，训练集与验证集之间有五个时间点的间隔（\(h\)）。

接下来，我们在更长的数据流（25 个时间点，含最初的那十五个）上训练学习算法。然后在（时间上）向前十个时间点处评估它的表现。

下面我们用 origami 的 folds_rolling_origin(n, first_window, validation_size, gap, batch) 函数演示滚动原点交叉验证方案的用法。要设置 folds_rolling_origin(n, first_window, validation_size, gap, batch)，我们需要：

  1. 希望交叉验证的时间点总数（n）；
  2. 第一个训练集的大小（first_window）；
  3. 验证集的大小（validation_size）；
  4. 训练集与验证集之间的间隔（gap）；以及
  5. 每轮交叉验证中训练集增长的步长（batch）。

滚动窗口（Rolling window）

滚动窗口交叉验证方案不像滚动原点那样在每轮迭代中往训练集里不断添加时间点，而是把训练样本沿时间向前”滚动” \(m\) 个（时间）单位。举例来说，这一策略在使用参数型学习算法时可能很有用——这类算法往往对矩（例如均值、方差）或参数的漂移非常敏感，而这种漂移本身又很难在建模阶段显式地纳入考虑。滚动窗口方案在计算上也更高效；在训练数据大到不便取用的流式数据分析场景中，它可能比滚动原点更合适。与滚动原点方案不同，滚动窗口方案每轮迭代中训练集里的抽样单元数目始终相同。

滚动原点 + \(V\) 折

滚动原点交叉验证方案的一个变体是滚动原点 \(V\) 折交叉验证方案，它把样本间的依赖也纳入考虑。与标准的滚动原点方案不同，在这一混合方案下，训练集与验证集中的抽样单元不再相同；它通过在时间序列设置中引入 \(V\) 折交叉验证来做到这一点。这里，学习算法的预测是在那些被排除于训练步骤之外的时间序列观测单元的未来时间点上评估的，从而既照顾到跨时间的潜在依赖，也照顾到跨观测单元的潜在依赖。要在 origami 中使用滚动原点 \(V\) 折交叉验证方案，可以调用 folds_vfold_rolling_origin_pooled(n, t, id, time, V, first_window, validation_size, gap, batch) 函数。下图中，我们展示 \(V=2\) 折，以及两个时间序列（滚动原点）交叉验证折。

origami 的总体工作流

在深入细节之前，我们先花点时间回顾 origami R 包中的一些基本功能。origami 的主力函数是 cross_validate()。开始之前，用户必须定义折结构，以及一个作用于每一折的函数（用 origami 的术语说，这个 cv_fun() 通常规定了候选学习算法如何被训练、其预测如何被验证）。

一旦传给 cross_validate()，这个主力函数就会把指定的函数（即 cv_fun()）逐折迭代应用，并以有意义的方式合并各折的结果。我们会在后面的小节中看到它的实际效果——现在，先给出这一过程各步骤的具体细节。

（1）定义折

传给 cross_validate 的 folds 对象是一个由折构成的 list；这样的 list 对象由辅助函数 make_folds() 生成。每一折都是一个 list，包含一个 "training" 索引向量、一个 "validation" 索引向量，以及一个 "fold_index"（它在整个折 list 中的次序）。make_folds() 函数支持前一节介绍的多种交叉验证方案。make_folds() 还可以保证某个给定变量各水平之间的均衡（通过 strata_ids 参数），也可以把同一独立单元上的所有观测保持在一起（通过 cluster_ids 参数）。

（2）定义折函数

cross_validate() 的 cv_fun 参数是一个自定义函数，它对每一折执行某些操作（同样，这通常是指候选学习算法的训练，以及在给定训练／验证划分——即单个折——上的评估）。该函数的第一个参数是 fold，它给出某个训练／验证划分中各单元的索引（注意，这第一个参数由 cross_validate() 自动传给 cv_fun()，其间它会向 make_folds() 生成的折对象取数）。额外参数可以通过 cross_validate() 的 ... 参数传给 cv_fun()。在该函数内部，可以使用便捷函数 training()、validation() 和 fold_index() 来取回折对象的各个组成部分。当 training() 或 validation() 函数接收到某个特定类的对象时，它们会以合理的方式对该对象取索引。例如，若输入对象是向量，这些辅助函数会直接对向量取索引；而若输入对象是 data.frame 或 matrix，它们会自动按行取索引。这让用户可以轻松地把数据划分为训练集与验证集。折函数必须返回一个带名字的结果 list，其中包含所需的各折输出。

（3）应用 cross_validate()

定义好折之后，就可以用 cross_validate() 函数把 cv_fun() 映射到各个 folds 上；其内部使用的是 lapply() 或 future_lapply()（后者是前者的并行化变体）。因此，只要指定一种并行化方案（即 R 的 future 并行框架 (Bengtsson 2021) 中的一个 plan），cross_validate() 就很容易并行化。应用 cross_validate() 会生成一个结果 list，与相应 cv_fun() 中所指定的自定义 list 相匹配。如上所述，每次调用 cv_fun() 本身都会返回一个结果 list，我们希望保存的每一类结果都有一个对应的具名槽位。cross_validate() 的主循环会生成一个由这些各折结果 list 构成的 list（即 list 的 list，或称”元 list”）。在内部，这个”元 list”会被整理（通过拼接），使得 cv_fun() 所指定的每一类结果只返回单个槽位（这同样是一个包含各折结果的 list）。默认情况下，combine_results() 辅助函数会以合理的方式把各折结果 list 合并起来。结果如何合并，是通过检查第一折结果的数据类型自动决定的。这一点可以通过在 .combine_control 参数中指定一个参数 list 来修改。

为解决这一问题，交叉验证允许某个特定流程（例如线性回归）在数据集的训练／验证划分上实施，并评估该流程在留出（验证）集上的拟合效果。在训练阶段未曾见过的数据上评估学习算法的质量，才能对算法的泛化误差给出诚实的评价。

借助 origami，我们可以很容易地把交叉验证纳入线性回归流程。首先，定义一个新函数，用于在数据集的某个特定划分（即某一折）上执行线性回归：

cv_lm <- function(fold, data, reg_form) {
  # get name and index of outcome variable from regression formula
  out_var <- as.character(unlist(str_split(reg_form, " "))[1])
  out_var_ind <- as.numeric(which(colnames(data) == out_var))

  # split up data into training and validation sets
  train_data <- training(data)
  valid_data <- validation(data)

  # fit linear model on training set and predict on validation set
  mod <- lm(as.formula(reg_form), data = train_data)
  preds <- predict(mod, newdata = valid_data)
  valid_data <- as.data.frame(valid_data)

  # capture results to be returned as output
  out <- list(
    coef = data.frame(t(coef(mod))),
    SE = (preds - valid_data[, out_var_ind])^2
  )
  return(out)
}

我们的 cv_lm() 函数相当简单：它把可用数据拆成互不相交的训练集与验证集（用 origami 中同名的那两个函数），在训练集上拟合线性模型，再在验证集上评估训练好的线性回归模型的质量。这就是 origami 所谓 cv_fun() 的一个简单例子——这类函数以交叉验证的方式，把某个特定例程应用到输入数据集上。

定义好这样的函数之后，我们只需用 origami 的 make_folds() 函数生成一组划分，再用 cross_validate() 把 cv_lm() 函数应用到得到的 folds 对象上。下面，我们用 make_folds() 与 cv_lm() 复现前面”手工”算过的那个重代入误差估计。

[1] 0.8656815

这（几乎）与我们上面得到的误差估计一致。

我们可以用 \(V\) 折交叉验证更诚实地评估误差：它把数据集划分为 \(V\) 个子集，在其中 \(V - 1\) 个子集上拟合算法（训练），并在被排除于拟合之外的那个子集上评估（验证）。如此反复，使每个留出子集都轮流充当验证集。借助 origami 的 cross_validate()，我们可以很容易地以这种方式应用 cv_lm() 函数（注意该函数默认执行 \(10\) 折交叉验证）：

# cross-validated estimate
folds <- make_folds(washb_data)
cvlm_results <- cross_validate(
  cv_fun = cv_lm, folds = folds, data = washb_data, reg_form = "whz ~ .",
  use_future = FALSE
)
mean(cvlm_results$SE, na.rm = TRUE)
[1] 1.140647

做完 10 折（默认值）的 \(V\) 折交叉验证后，我们很快就会发现，先前（用重代入得到的）模型误差估计有点过于乐观了。线性回归模型误差的诚实估计要更大！

随机森林的交叉验证

为进一步考察 origami，让我们回到使用 WASH Benefits 数据集的示例分析。这里我们要写一个新的 cv_fun() 函数。作为例子，我们使用 Breiman 的随机森林算法 (Breiman 2001)，它由 randomForest 包中的 randomForest() 函数实现：

cv_rf <- function(fold, data, reg_form) {
  # get name and index of outcome variable from regression formula
  out_var <- as.character(unlist(str_split(reg_form, " "))[1])
  out_var_ind <- as.numeric(which(colnames(data) == out_var))

  # define training and validation sets based on input object of class "folds"
  train_data <- training(data)
  valid_data <- validation(data)

  # fit Random Forest regression on training set and predict on holdout set
  mod <- randomForest(formula = as.formula(reg_form), data = train_data)
  preds <- predict(mod, newdata = valid_data)
  valid_data <- as.data.frame(valid_data)

  # define output object to be returned as list (for flexibility)
  out <- list(
    coef = data.frame(mod$coefs),
    SE = ((preds - valid_data[, out_var_ind])^2)
  )
  return(out)
}

cv_rf() 函数对 randomForest 算法的训练与评估做交叉验证，它以我们先前的 cv_lm() 函数为模板。目前，各个 cv_fun() 还必须手工编写；不过在该包未来的版本中，可能会提供一个包装器，支持自动生成供 origami 使用的 cv_fun。

下面，我们用 cross_validate() 把自定义的 cv_rf() 函数应用到 make_folds() 生成的 folds 对象上：

# now, let's cross-validate...
folds <- make_folds(washb_data)
cvrf_results <- cross_validate(
  cv_fun = cv_rf, folds = folds,
  data = washb_data, reg_form = "whz ~ .",
  use_future = FALSE
)
mean(cvrf_results$SE)
[1] 1.004166

用 10 折的 \(V\) 折交叉验证，我们得到了这个随机森林预测误差的诚实估计。这是一个例子，说明只要有合适的 cv_fun() 函数，origami 的 cross_validate() 流程就可以推广到任意估计技术。

# function to calculate cross-validated squared error
cv_forecasts <- function(fold, data) {
  # Get training and validation data
  train_data <- training(data)
  valid_data <- validation(data)
  valid_size <- length(valid_data)

  train_ts <- ts(log10(train_data), frequency = 12)

  # First arima model
  arima_fit <- arima(train_ts, c(0, 1, 1),
    seasonal = list(
      order = c(0, 1, 1),
      period = 12
    )
  )
  raw_arima_pred <- predict(arima_fit, n.ahead = valid_size)
  arima_pred <- 10^raw_arima_pred$pred
  arima_MSE <- mean((arima_pred - valid_data)^2)

  # Second arima model
  arima_fit2 <- arima(train_ts, c(5, 1, 1),
    seasonal = list(
      order = c(0, 1, 1),
      period = 12
    )
  )
  raw_arima_pred2 <- predict(arima_fit2, n.ahead = valid_size)
  arima_pred2 <- 10^raw_arima_pred2$pred
  arima_MSE2 <- mean((arima_pred2 - valid_data)^2)

  out <- list(mse = data.frame(
    fold = fold_index(),
    arima = arima_MSE, arima2 = arima_MSE2
  ))
  return(out)
}
