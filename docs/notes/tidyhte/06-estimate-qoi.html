6. estimate_QoI()：五类关心量

tidyhte 包函数手册

estimate_QoI(data, ...)

... 是不加引号的调节变量名，每一个都必须在 add_moderator() 里登记过 （见第 2 页）；一个都不给时， 自动使用 MCATE_cfg 里登记的全部变量。 本页按 estimate_QoI() 内部的执行顺序讲五类关心量。

输出的长格式 schema

不管算了哪几类，返回的都是同一张表，最多六列：

列 含义 什么时候是 NA
estimand 量的名字：MCATE、PCATE、VIMP、SATE、PATE、Predicted CATE、MSE、AUC、RROC、SL risk、SL coefficient 从不
term 变量名 / 子模型名 ATE 行为 NA
value 连续取值（连续调节变量的评估点、RROC 的横轴） 离散量为 NA
level 离散取值（因子水平、Propensity Score / Treatment Response / Control Response / Effect Surface） 连续量为 NA
estimate 点估计 从不
std_error 标准误 RROC、Predicted CATE 恒为 NA

注记sample_size 被最后一行 select() 丢掉了

calculate_ate() 和 PCATE 的内核都算了 sample_size 一列， 但 estimate_QoI() 收尾时写的是 select(intersect(col_order, names(.)))，而 col_order 只有上表那六个名字。 于是 ATE 的样本量（以及 PCATE 每个评估点的有效样本量）在公开输出里拿不到， 只能自己从数据框数。

QoI_cfg：开关总表

QoI_cfg$new(mcate = NULL, pcate = NULL, vimp = NULL, diag = NULL,
            ate = TRUE, predictions = FALSE)
字段 类型 basic_config() 的默认值 对应内核
mcate MCATE_cfg / NULL NULL（靠 add_moderator() 建） calculate_mcate_quantities()
pcate PCATE_cfg / NULL NULL（配方 API 无入口） fit_fx_predictor() + calculate_pcate_quantities()
vimp VIMP_cfg / NULL VIMP_cfg$new(sample_splitting = TRUE) calculate_vimp() / calculate_linear_vimp()
diag Diagnostics_cfg / NULL 三处诊断都有 calculate_diagnostics()
ate 逻辑 TRUE calculate_ate()
predictions 逻辑 FALSE 与 PCATE 共用 fit_fx_predictor()

执行顺序固定为 MCATE → （效应面模型）→ PCATE → VIMP → 诊断 → ATE， 最后 bind_rows()。顺序之所以重要：效应面模型只有在这一步被拟合， 诊断在它之后才看得到 .pseudo_outcome_hat。

注意裸的 QoI_cfg$new() 六项里有四项是 NULL， 所以 HTE_cfg$new() 直接构造出来的配方既没有 VIMP 也没有任何诊断， 和 basic_config() 不是一回事。

MCATE：边际条件平均治疗效应

“边际”指的是其余协变量全部积掉，只保留一个调节变量。 这就是文献里通常说的 CATE，也是本包的主力输出。

MCATE_cfg$new(cfgs, std_errors = TRUE)
MCATE_cfg$add_moderator(var_name, cfg)

cfgs 是”变量名 → 展示模型”的命名列表，add_moderator() 配方函数 帮你填的就是它。对每个变量，内核做的事只有三步： 用 .pseudo_outcome 当标签、该变量当唯一特征建 Model_data， 按展示模型拟合，取 predict_se()。

注记标准误怎么来的

离散变量走 StratifiedPredictor，每层是加权均值 + 聚类稳健标准误 （聚类单位是 make_splits() 里的标识符）。 连续变量走 nprobust::lprobust() 的局部线性回归， 标准误是它给的（不做聚类调整）。 MCATE_cfg$std_errors <- FALSE 时两者都只返回点估计， std_error 列在合并后成为 NA。

VIMP：调节变量重要性

VIMP_cfg$new(sample_splitting = TRUE, linear_only = FALSE)

两条路径算的是不同的量：

linear = FALSE（默认） linear = TRUE
内核 calculate_vimp() calculate_linear_vimp()
依赖 vimp + quadprog + SuperLearner 只用 stats::lm()
估计量 去掉该变量后总体 \(R^2\) 的下降 去掉该变量后平方残差均值的上升
量纲 无量纲，截断在 \([0, 1]\) 结局量纲的平方
速度 要拟合 \(1 + p\) 个 CV.SuperLearner 一个 lm + \(p\) 个 lm
有效性 算法无关，需要效应面模型收敛 只有真模型是线性时才一致 
cfg_np <- make_cfg() %>% add_vimp(sample_splitting = FALSE)
cfg_ln <- make_cfg(); cfg_ln$qoi$vimp <- VIMP_cfg$new(sample_splitting = FALSE, linear_only = TRUE)
cfg_ss <- make_cfg() %>% add_vimp(sample_splitting = TRUE)

}

重要用配方 API 打不开线性路径

三个必须记住的约束：

  1. 折数必须是偶数，否则 calculate_vimp() 抛 Number of splits must be even to calculate VIMP.； make_splits() 在配方已挂上时会自动向上取偶。
  2. VIMP 对哪些变量算，取决于 estimate_QoI() 的 ...， 而不是 VIMP_cfg。少传一个变量，它就不在重要性表里， 而且剩下变量的重要性值会变（因为”全模型”变小了）。
  3. 因子按整体剔除。VIMP 用的是 Model_data$model_frame（原始列）， 不是哑变量矩阵，所以一个三水平因子算作一个变量。
# 先用不带 VIMP 的配方划 3 折（这样不会被自动取偶），再换上带 VIMP 的配方

PCATE：偏条件平均治疗效应

PCATE_cfg$new(model_covariates, cfgs, num_mc_samples = 100)

[实验性]。它先在全部 model_covariates 上拟合一个交叉拟合的效应面模型 \(\hat\tau(x)\)，再把关心的那个协变量在其取值范围上扫一遍、 其余协变量按经验分布蒙特卡洛积分，得到”控制住其它变量之后”的效应曲面。 和 MCATE 的区别正是”偏”与”边际”：两个高度相关的变量， MCATE 曲面会很像，PCATE 曲面可以完全不同。

cfg_pc <- make_cfg()
cfg_pc$qoi$pcate <- PCATE_cfg$new(
  model_covariates = c("x1", "x2", "x3", "x4"),
  # cfgs 的内容不会用于展示（见下方 callout），但它的**名字**决定 num_mc_samples
  cfgs = list(x1 = KernelSmooth_cfg$new(neval = 7), x2 = Stratified_cfg$new("x2")),
  num_mc_samples = 20
)
d_pc <- prepped; attr(d_pc, "HTE_cfg") <- cfg_pc
res_pc <- suppressWarnings(estimate_QoI(d_pc, x1, x2))
count(res_pc, estimand, level)

警告每次调用都会打印一句劝退

这是包作者刻意放的：PCATE 没有”其它变量也被随机化”这一条件时， 不具备干净的因果解释，本质上更接近偏依赖图。 把它当描述性工具用，别当成因果估计量。

警告cfgs 虽然不用于展示，却决定 num_mc_samples 的名字

PCATE_cfg$new() 里对标量 num_mc_samples 的处理是

self$num_mc_samples <- as.list(structure(rep(num_mc_samples, length(cfgs)),
                                         names = names(cfgs)))

——按 cfgs 的名字展开，而不是按 model_covariates。 而 FX.Predictor$predict() 取的是 self$num_mc_samples[[covariate]]。于是只要你向 estimate_QoI() 要一个不在 cfgs 名字里的 PCATE，抽样数就是缺失值， 报一个来自 dplyr::sample_n() 的错：

cfg_bad <- make_cfg()
cfg_bad$qoi$pcate <- PCATE_cfg$new(
  model_covariates = c("x1", "x2", "x3", "x4"),
  cfgs = list(x1 = KernelSmooth_cfg$new()),   # 只有 x1
  num_mc_samples = 20)
d_bad <- prepped; attr(d_bad, "HTE_cfg") <- cfg_bad
suppressWarnings(estimate_QoI(d_bad, x1, x2))   # 却要了 x2
#> Error in `dplyr::sample_n()`:
#> ! Can't compute indices.
#> Caused by error in `if (size <= n || replace) ...`:
#> ! missing value where TRUE/FALSE needed

稳妥写法是把 num_mc_samples 直接写成覆盖全部目标变量的命名列表：

cfg_ok <- make_cfg()
cfg_ok$qoi$pcate <- PCATE_cfg$new(
  model_covariates = c("x1", "x2", "x3", "x4"),
  cfgs = list(),                                   # 反正也不会被读
  num_mc_samples = list(x1 = 20, x2 = 20))
d_ok <- prepped; attr(d_ok, "HTE_cfg") <- cfg_ok
suppressWarnings(estimate_QoI(d_ok, x1, x2)) %>% filter(estimand == "PCATE") %>% count(term)
#> # A tibble: 2 × 2
#>   term      n
#>   <chr> <int>
#> 1 x1       30
#> 2 x2        3

num_mc_samples 控制蒙特卡洛积分的抽样数（大于样本量时就用全样本）。 它直接决定这一步的耗时：内部对每个唯一取值抽 num_mc_samples 行、 逐折预测，因此离散变量的成本随水平数线性增长。

底层对象是 FX.Predictor（未导出），由 fit_fx_predictor() 构造： 它保存 K 个交叉拟合模型，$predict(data, covariate) 返回 covariate_value / .hte / .id 三列的长表。
