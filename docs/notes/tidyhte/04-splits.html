4. make_splits() 与三个数据对象

tidyhte 包函数手册

交叉拟合的折是整条流水线的地基：它同时决定了聚类稳健标准误的聚类单位、 SuperLearner 内层交叉验证的折数，以及 VIMP 能不能算。 这一步做错，后面所有数字都跟着错，而且多数情况下不会报错。

make_splits()

make_splits(data, identifier, ..., .num_splits)
参数 类型 说明
data 数据框 通常已经 attach_config() 过（不是必须，但见下面的偶数折规则）
identifier 不加引号的列名 单位或聚类的标识符；同一标识符的所有行进同一折
... 不加引号的列名 分层用的协变量；需要 quickblock
.num_splits 整数 折数；要算 VIMP 时必须是偶数（会自动向上取偶）

返回原数据框，加一列 .split_id，加两个 attribute（num_splits、identifier）。

cfg <- basic_config() %>% add_known_propensity_score("ps") %>%
  add_moderator("Stratified", x2) %>% remove_vimp()
#> Super Learner
#> Version: 2.0-42
#> Package created on 2026-09-14
s <- sim %>% attach_config(cfg) %>% make_splits(uid, .num_splits = 4)
table(s$.split_id)
#> 
#>   1   2   3   4 
#> 200 200 200 200
c(num_splits = attr(s, "num_splits"), identifier = attr(s, "identifier"))
#> num_splits identifier 
#>        "4"      "uid"

折数不能小于 3

SuperLearner 的内层交叉验证并不是独立设定的， 而是直接拿训练集里剩下的外层折当内层折用：

tidyhte::Model_data$public_methods$SL_cv_control
#> function () 
#> {
#>     validRows <- purrr::map(sort(unique(self$split_id)), ~which(.x == 
#>         self$split_id))
#>     SuperLearner::SuperLearner.CV.control(V = length(validRows), 
#>         validRows = validRows)
#> }
#> <bytecode: 0x0000025595048038>
#> <environment: namespace:tidyhte>

于是内层折数恒等于 .num_splits - 1：

vapply(c(2, 3, 4, 6), function(k) {
  dd   <- make_splits(sim, uid, .num_splits = k)
  fold <- tidyhte:::split_data(dd, 1)
  Model_data$new(fold$train, y, x1, x2)$SL_cv_control()$V
}, numeric(1)) |> setNames(paste0(".num_splits = ", c(2, 3, 4, 6)))
#> .num_splits = 2 .num_splits = 3 .num_splits = 4 .num_splits = 6 
#>               1               2               3               5

.num_splits = 2 时内层 \(V = 1\)：唯一那一折全部是验证集，训练集为空， 每个学习器都在 0 行数据上拟合失败，SuperLearner 把它们全部剔除后报错：

cfg2 <- basic_config() %>% add_known_propensity_score("ps") %>%
  add_moderator("Stratified", x2) %>% remove_vimp()
sim %>% attach_config(cfg2) %>% make_splits(uid, .num_splits = 2) %>%
  produce_plugin_estimates(y, a, x1, x2, x3, x4)
#> Warning in glm.fit(x = structure(numeric(0), dim = c(0L, 7L), dimnames = list(:
#> no observations informative at iteration 1
#> Warning: glm.fit: algorithm did not converge
#> Error in glm.fit(x = structure(numeric(0), dim = c(0L, 7L), dimnames = list( : 
#>   object 'fit' not found
#> Warning in FUN(X[[i]], ...): Error in algorithm SL.glm 
#>   The Algorithm will be removed from the Super Learner (i.e. given weight 0)
#> Error in SuperLearner::SuperLearner(Y = data$label, X = X_df, family = self$family, : All algorithms dropped from library
重要All algorithms dropped from library 的三种成因

这句报错来自 SuperLearner，本身不指向病因。实测下来在 tidyhte 里有三种来源：

  1. 折数为 2（上面这种），训练集为空；
  2. 稀有因子水平：某折的训练集里缺了某个水平， predict.lm 抛 factor x has new levels， 如果库里只有一个学习器就会被全部剔除。多放几个 （SL.glmnet 等基于 model.matrix 的）可以让这类错误退化成打印一行、继续跑；
  3. 协变量常数或共线到 glm.fit 不收敛。

三者的共同表现是先在 stderr 上打印一串 Error in algorithm SL.xxx 的警告，然后才抛这句。看到它先回头数折数和每折的稀有水平频数。

要算 VIMP 时折数被强制取偶

cfg_v <- basic_config() %>% add_moderator("Stratified", x2) %>%
  add_moderator("KernelSmooth", x1) %>% add_vimp(sample_splitting = FALSE)

msgs <- character()
sv <- withCallingHandlers(
  sim %>% attach_config(cfg_v) %>% make_splits(uid, .num_splits = 3),
  message = function(m) { msgs <<- c(msgs, conditionMessage(m)); invokeRestart("muffleMessage") }
)
grep("num_splits", msgs, value = TRUE)
#> [1] "`num_splits` must be even if VIMP is requested as a QoI. Rounding up.\n"
attr(sv, "num_splits")    # 要的是 3，拿到的是 4
#> [1] 4

注意这条规则依赖 attach_config() 已经调用过——make_splits() 先检查数据框上有没有 HTE_cfg，没有就当作不需要 VIMP。 先 make_splits() 再 attach_config() 的写法能跑， 但奇数折会一路带到 estimate_QoI() 才炸：

d_odd <- sim %>% make_splits(uid, .num_splits = 3) %>% attach_config(cfg_v) %>%
  produce_plugin_estimates(y, a, x1, x2, x3, x4) %>% construct_pseudo_outcomes(y, a)
estimate_QoI(d_odd, x2)
#> Error in calculate_vimp(data, {: Number of splits must be even to calculate VIMP.

聚类：同一标识符进同一折

标识符允许重复，重复就意味着聚类。make_splits() 先按标识符 tally() 再分配折，所以一个聚类的所有行必然落在同一折； 下游 Model_data$cluster 用同一列做聚类稳健标准误。

set.seed(1)
clustered <- tibble(vid = rep(1:150, each = 4), x1 = rnorm(600))
cs <- make_splits(clustered, vid, .num_splits = 4)
# 每个 vid 只出现在一个折里
all(tapply(cs$.split_id, cs$vid, \(z) length(unique(z))) == 1)
#> [1] TRUE
table(cs$.split_id)
#> 
#>   1   2   3   4 
#> 152 148 152 148

这是把聚类设计告诉 tidyhte 的唯一入口： calculate_ate()、estimate_diagnostic("MSE")、 线性 VIMP 都调用 clustered_se_of_mean(..., data[[id_col]])， 聚类层次完全由这一列决定。

分层：quickblock 区组

... 里给协变量就会启用 Higgins, Sävje & Sekhon (2016) 的贪婪阈值区组： 先把单位聚成大小至少为 .num_splits 的区组（欧氏距离）， 再在每个区组内把折号随机置换一遍。效果是各折的协变量分布更接近：

set.seed(2)
plain <- make_splits(sim, uid, .num_splits = 4)
block <- make_splits(sim, uid, x1, x3, x2, .num_splits = 4)
rbind(
  纯随机 = round(tapply(sim$x1, plain$.split_id, mean), 3),
  分层   = round(tapply(sim$x1, block$.split_id, mean), 3)
)
#>            1      2      3      4
#> 纯随机 0.053 -0.073  0.045 -0.010
#> 分层   0.017  0.042 -0.027 -0.021
注记没装 quickblock 会静默降级

源码里先 package_present("quickblock")，缺了就打印 `quickblock` is not installed, so falling back to un-stratified CV. 然后按纯随机划分继续。这是 message 而不是 warning， 在 message = FALSE 的 Rmd / Quarto 代码块里完全看不到—— 分层折悄悄变成了随机折。要确认分层真的生效， 最稳的办法是像上面那样比一下各折的协变量均值。

警告分层变量有缺失 → .split_id 变成 NA，后果取决于它是不是协变量

make_splits() 对 ... 里的变量做 listwise 删除， 被删掉的行仍留在返回的数据框里，只是 .split_id 为 NA。 它只打印一句 Dropped 40 of 800 rows (5%) through listwise deletion.， 而这是 message，在 message = FALSE 的代码块里看不见。

sim_na <- sim; sim_na$x1[1:40] <- NA
sna <- make_splits(sim_na, uid, x1, x2, .num_splits = 4)
attr(sna, "HTE_cfg") <- cfg
table(sna$.split_id, useNA = "ifany")
#> 
#>    1    2    3    4 <NA> 
#>  190  182  196  192   40

接下来分两种情况，都不好：

① 那个变量也在模型协变量里——produce_plugin_estimates() 自己再做一次 listwise 删除，这些行被排除在估计之外， 返回的数据框里它们的预测是 NA（静默）：

z <- produce_plugin_estimates(sna, y, a, x1, x2, x3)
c(pi_hat缺失 = sum(is.na(z$.pi_hat)), mu1缺失 = sum(is.na(z$.mu1_hat)))
#> pi_hat缺失    mu1缺失 
#>         40         40

② 那个变量不在模型协变量里（“只用来分层”是很自然的做法）—— 这些行通过了 listwise 删除，却带着 NA 的折号进入主循环， 在把预测写回原位置时报一个与病因无关的错：

produce_plugin_estimates(sna, y, a, x2, x3)
#> Error in pi_hat[folds$in_holdout] <- a_model$pi$predict(pred_data)$estimate: NAs are not allowed in subscripted assignments

所以分层变量的缺失必须在 make_splits() 之前自己处理掉。

警告缺失把一整折抽空时，VIMP 报 Number of splits is inconsistent.

calculate_vimp() 会核对”数据里实际出现的折数”与 num_splits attribute 是否一致。如果某一折的单位恰好都因缺失被删掉（分层抽样、按时间段收集的 数据里并不罕见），两者就对不上：

d3 <- sim %>% attach_config(cfg_v) %>% make_splits(uid, .num_splits = 4)
d3$x1[d3$.split_id == 3] <- NA          # 第 3 折整折缺失
d3 <- d3 %>% produce_plugin_estimates(y, a, x1, x2, x3, x4) %>%
  construct_pseudo_outcomes(y, a)
estimate_QoI(d3, x1, x2)
#> Error in calculate_vimp(data, {: Number of splits is inconsistent.

split_data() 与 HTEFold

tidyhte:::split_data(data, split_id)

把数据切成训练 / 留出两半，返回一个 HTEFold R6 对象。 produce_plugin_estimates() 的主循环就是在它上面跑的。

fold <- tidyhte:::split_data(s, 2)
class(fold)
#> [1] "HTEFold" "R6"
c(train = nrow(fold$train), holdout = nrow(fold$holdout), in_holdout = sum(fold$in_holdout))
#>      train    holdout in_holdout 
#>        600        200        200
字段 内容
train .split_id != split_id 的那部分，用来拟合
holdout .split_id == split_id 的那部分，用来预测
in_holdout 长度为 \(n\) 的逻辑向量，方便把预测值写回原位置

也就是留一折做预测、其余折做训练（K 折交叉拟合）， 和”训练集小、验证集大”的直觉正好相反—— 这解释了为什么 .num_splits 越大，每次拟合用的数据越多。

Model_data

Model_data$new(data, label_col, ..., .weight_col = NULL)

所有模型拿到的都是这个对象，它把数据框标准化成 “标签向量 + 设计矩阵 + 折号 + 聚类 + 权重”：

md <- Model_data$new(s, y, x1, x2, x3)
c(label = length(md$label), 行 = nrow(md$features), 列 = ncol(md$features))
#> label    行    列 
#>   800   800     5
colnames(md$features)
#> [1] "x1"  "x2a" "x2b" "x2c" "x3"
c(num_splits = md$num_splits, 权重前三 = head(md$weights, 3), 聚类前三 = head(md$cluster, 3))
#> num_splits  权重前三1  权重前三2  权重前三3  聚类前三1  聚类前三2  聚类前三3 
#>          4          1          1          1          1          2          3
字段 构造方式 注意
label label_col 那一列 传 NULL 表示”只要特征”（预测时用）
features stats::model.matrix() 因子会被拆成哑变量，列名形如 x2b、x2c
model_frame stats::model.frame() 保留原始列，VIMP 按原始列逐个剔除
split_id .split_id
cluster 标识符列 聚类稳健标准误用
weights .weight_col，缺省全 1

features 和 model_frame 的区别很重要： MCATE / 效应面模型用的是 features（哑变量）， 而 VIMP 用的是 model_frame，所以一个 \(k\) 水平的因子在 VIMP 里 算作一个变量整体剔除，而不是 \(k-1\) 个哑变量各剔各的。

names(md$model_frame)
#> [1] "x1" "x2" "x3"
