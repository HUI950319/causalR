tidyhte 包函数手册

基于 1.0.4 的逐函数用法说明与本机实测

tidyhte 把 Kennedy (2023) 的 DR-learner 落成一条 tidy 风格的四步流水线： 先写一份”配方”（recipe）说明用哪些机器学习模型估计冗余函数， 再把配方贴在数据框上，顺着 make_splits() → produce_plugin_estimates() → construct_pseudo_outcomes() → estimate_QoI() 走一遍，最后拿到一个长格式 tibble，里面是 ATE、各调节变量的 CATE 曲面、 变量重要性和模型诊断。画图交给使用者，包本身不产出任何图形对象。

本部分是该包的函数用法手册，逐个覆盖包内 54 个帮助主题 （pkgdown 站点、 CRAN 参考手册）。 每页给出参数逐项说明、可直接运行的代码、返回对象的结构， 以及本机实际运行后发现的默认值陷阱与失效路径。

核对环境与证据边界

本手册核对截止 2026 年 9 月 20 日，环境为：

项目 值
包版本 tidyhte 1.0.4（2025-07-29，MIT，维护者 Drew Dimmery）
R Windows R 4.4.3
Imports checkmate、dplyr、lifecycle、magrittr、progress、purrr、R6、rlang、SuperLearner、tibble

证据分三级，正文中逐处标明：

  1. 文档——包自带帮助页、三个 vignette 与 DESCRIPTION 的原文；
  2. 源码——本机已安装包的函数体（tidyhte::: 可复核）；
  3. 实测——在上述环境下实际运行的输出。

本手册的代码块由本站渲染时真实执行，页面上的输出与图形就是本机结果。 随机过程已固定种子（set.seed(20260920)）。

重要七处与官方文档不一致的实测结论

在展开之前先给出结论，它们影响所有使用者：

  1. 配方 API 造不出 logistic 倾向得分模型。 SLEnsemble_cfg 的默认 family 是 stats::gaussian()，add_propensity_score_model() 只往集成里塞学习器、 从不改 family，也没有任何参数能改它。于是倾向得分是线性概率模型， 实测 .pi_hat 落在 \([-0.006,\ 0.911]\)，一个近零的倾向把某个单位的 DR 伪结局 压到 \(-169\)，SATE 从 0.726 掉到 0.517（真值 0.701）。 见第 3 页。
  2. HTE_cfg 是 R6 对象，管道不复制它。 variant <- base %>% add_outcome_model(...) 会把 base 一起改掉（identical(base, variant) 为 TRUE）， 连数据框上已经 attach_config() 挂好的那份也跟着变； 而且 $clone() 浅拷贝不够，必须 $clone(deep = TRUE)。 “同一份配方跑多个结局”正是作者在 vignette 里推荐的用法。 见第 2 页。
  3. add_vimp(linear_only = TRUE) 是空操作。 函数签名收下这个参数， 函数体却只写了 VIMP_cfg$new(sample_splitting = sample_splitting)， linear_only 从未传下去。要用线性 VIMP 只能手工替换 cfg$qoi$vimp。 见第 2 页。
  4. add_effect_model() 与 add_effect_diagnostic() 在默认流程里几乎不起作用。 效应面模型只有 VIMP 会用到；“Effect Surface” 的诊断一律被跳过并打印 Skipping diagnostic on .pseudo_outcome due to lack of model.， 除非额外配置 PCATE_cfg 或 predictions = TRUE。 官方 vignette 那三张 facet_wrap(~level) 图里的 Effect Surface 面板是空的。 见第 6 页。
  5. .num_splits 不能小于 3。 SuperLearner 的内层交叉验证直接复用外层 split id （Model_data$SL_cv_control()），.num_splits = 2 时训练集只剩一个 fold， 训练集为空，报 All algorithms dropped from library。 同时 SLEnsemble_cfg$new(cvControl = ) 存下来的值从未被使用。 见第 4 页。
  6. predictions = TRUE 在没有 PCATE_cfg 时直接报错 （'.' in formula and no 'data' argument）；即使补上 PCATE， Predicted CATE 那些行的 level 列写的是标识符列名（"uid"） 而不是每个单位的 id，预测值只能靠行序对回原数据。 见第 6 页。
  7. 权重与连续调节变量互斥。 nprobust 不支持权重， produce_plugin_estimates(.weights = w) 配上任何 KernelSmooth 调节变量， estimate_QoI() 就抛 `nprobust` does not support the use of weights.。 见第 5 页。

另有若干 documented-but-broken 的路径（Constant_cfg 在默认设置下抛 Not Implemented、PCATE_cfg$cfgs 被忽略、RROC 的 nbins 默认是样本量而非 100、 未知诊断名报 object 'result' not found）汇总在 第 8 页。

这个包在做什么

给定 \((X_i, A_i, Y_i)\)，记两个冗余函数

\[ \pi(x) \equiv \mathbb{P}(A = 1 \mid X = x), \qquad \mu_a(x) \equiv \mathbb{E}(Y \mid X = x, A = a), \]

在一致性、无未测混杂、正值性下，条件平均治疗效应 \(\tau(x) = \mu_1(x) - \mu_0(x) = \mathbb{E}[Y(1) - Y(0) \mid X = x]\)。 DR-learner 的做法是先交叉拟合出 \((\hat\pi, \hat\mu_0, \hat\mu_1)\)， 再把它们压成一个伪结局

\[ \hat\psi(Z) = \frac{A - \hat\pi(X)}{\hat\pi(X)\{1 - \hat\pi(X)\}} \bigl\{Y - \hat\mu_A(X)\bigr\} + \hat\mu_1(X) - \hat\mu_0(X), \]

它的条件期望就是 \(\tau(x)\)。此后任何对 \(\hat\psi\) 的回归、分组平均、 变量重要性，都可以当成是对个体治疗效应本身做的。 tidyhte 的四个函数正好对应这四步：

原始数据 + HTE_cfg（配方）
   │  attach_config()：把配方挂成数据框的一个 attribute
   ▼
   │  ① make_splits()：按单位标识符（可选分层）划 K 折 → .split_id
   ▼
   │  ② produce_plugin_estimates()：交叉拟合三个冗余模型
   ▼            → .pi_hat, .mu0_hat, .mu1_hat
   │  ③ construct_pseudo_outcomes()：压成一列 → .pseudo_outcome
   ▼
   │  ④ estimate_QoI()：对伪结局做各种"二阶段回归"
   ▼
长格式 tibble：estimand / term / value / level / estimate / std_error

四步之间靠数据框的 attribute 传递状态（HTE_cfg、num_splits、 identifier、weights、treatment、outcome、SL_coefs）， 这是这个包最需要注意的设计—— 第 1 页有完整清单和会把它们弄丢的操作。

警告默认配方只有 SL.glm，而且倾向得分用的是高斯族

basic_config() 给三处模型（倾向、结局、效应面）各建一个只含 SL.glm 的 SuperLearner 集成，family 全部是 stats::gaussian()。 也就是说，不加任何 add_*_model() 时，整条流水线退化成线性回归， 倾向得分还是线性概率模型。这和”用机器学习集成估计冗余函数”的宣传 差距很大，而配方 API 里没有改 family 的入口。 对照实测见第 3 页。

最小可运行例子

library(tidyhte)
library(dplyr)

set.seed(20260920)
n <- 800
sim <- tibble(
  uid = seq_len(n),
  x1  = rnorm(n),                                        # 真效应修饰变量
  x2  = factor(sample(c("a", "b", "c"), n, replace = TRUE)),  # 真效应修饰变量
  x3  = runif(n, -2, 2),                                 # 只影响基线（预后）
  x4  = rnorm(n)                                         # 纯噪声
) %>% mutate(
  ps  = plogis(0.6 * x1 - 0.5 * (x2 == "c") + 0.3 * x3), # 真倾向得分
  a   = rbinom(n, 1, ps),
  tau = 0.5 + 0.8 * x1 + 0.6 * (x2 == "c"),              # 真 CATE
  y   = 1 + x1 + 0.5 * x3 + tau * a + rnorm(n, sd = 0.5)
)

cfg <- basic_config() %>%
  add_known_propensity_score("ps") %>%
  add_outcome_model("SL.glm.interaction") %>%
  add_effect_model("SL.glm.interaction") %>%
  add_moderator("Stratified", x2) %>%
  add_moderator("KernelSmooth", x1, x3, x4) %>%
  add_vimp(sample_splitting = FALSE)

results <- sim %>%
  attach_config(cfg) %>%
  make_splits(uid, .num_splits = 4) %>%
  produce_plugin_estimates(y, a, x1, x2, x3, x4) %>%
  construct_pseudo_outcomes(y, a) %>%
  estimate_QoI(x1, x2, x3, x4)

filter(results, estimand %in% c("SATE", "VIMP"))
#> # A tibble: 5 × 6
#>   estimand term  value level estimate std_error
#>   <chr>    <chr> <dbl> <chr>    <dbl>     <dbl>
#> 1 VIMP     x1       NA <NA>    0.247    0.0441 
#> 2 VIMP     x2       NA <NA>    0.0429   0.0134 
#> 3 VIMP     x3       NA <NA>    0        0.00305
#> 4 VIMP     x4       NA <NA>    0        0.00242
#> 5 SATE     <NA>     NA <NA>    0.728    0.0495

filter(results, estimand == "MCATE", term == "x2") %>%
  arrange(level) %>%
  mutate(truth = round(tapply(sim$tau, sim$x2, mean), 3))
